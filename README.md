# OFFSHOREATSEA_JOB — бот автопостинга вакансий

Готовый бот: принимает вакансии текстом в личке, приводит к единому шаблону
(судно/регион/дата/ротация/требования/контакт + автохэштеги), проверяет
дубликаты, публикует сразу или ставит в очередь дайджеста, считает клики
по кнопке «Откликнуться».

## Быстрый старт

### 1. Создайте бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`
2. Придумайте имя и username (заканчивается на `bot`)
3. Скопируйте токен, который пришлёт BotFather

### 2. Узнайте свой Telegram ID

Напишите [@userinfobot](https://t.me/userinfobot) — пришлёт ваш числовой ID.

### 3. Добавьте бота в канал администратором

Настройки канала → Администраторы → Добавить → найдите бота по username →
дайте право «Публикация сообщений».

### 4. Получите ключ Anthropic API (для разбора вакансий)

Бот разбирает текст вакансии на поля через Claude — это отдельный от
Claude.ai сервис, платный по использованию (копейки за один разбор текста).

1. Зайдите на [console.anthropic.com](https://console.anthropic.com) → зарегистрируйтесь
2. Settings → API Keys → Create Key → скопируйте ключ (вида `sk-ant-...`)
3. Добавьте баланс на счёт (Billing) — без этого запросы не пройдут

### 5. Заполните конфиг

Скопируйте `.env.example` в `.env` и впишите:
- `BOT_TOKEN` — из шага 1
- `BOT_USERNAME` — username бота без `@`
- `ADMIN_IDS` — ваш ID из шага 2
- `CHANNEL_USERNAME` — username канала без `@` (сейчас `offshoreatsea`)
- `APPLY_BOT_LINK` — куда вести кнопку «Apply» (пока можно оставить
  ссылку на сам канал, поменять — дело одной строчки в `.env`)
- `ANTHROPIC_API_KEY` — ключ из шага 4

### 6. Деплой на Railway (бесплатно, без сервера)

1. Зарегистрируйтесь на [railway.app](https://railway.app) через GitHub
2. Залейте эту папку целиком в новый репозиторий на GitHub
   (через веб-интерфейс GitHub — кнопка "Add file" → "Upload files",
   консоль не обязательна; **файл `.env` не загружайте**, только `.env.example`)
3. В Railway: **New Project → Deploy from GitHub repo** → выберите репозиторий
4. Во вкладке **Variables** добавьте все переменные из вашего `.env`
   (`BOT_TOKEN`, `BOT_USERNAME`, `ADMIN_IDS`, `CHANNEL_USERNAME`, `APPLY_BOT_LINK`,
   `ANTHROPIC_API_KEY`)
5. Railway сам поставит зависимости и запустит бота (используется `Procfile`)
6. Проверьте вкладку **Deployments → Logs** — ошибок быть не должно
7. Откройте бота в Telegram, отправьте `/start` — должен ответить

### Если бот не публикует пост в канал

Бот теперь сам пришлёт текст ошибки в чат при неудачной публикации. Самая
частая причина: он не добавлен администратором канала или у него нет права
«Публикация сообщений» — проверьте в настройках канала → Администраторы.

Если хотите добавить свой часовой пояс для дайджест-расписания (по умолчанию
Railway использует UTC) — добавьте переменную `TZ` со значением вашего пояса,
например `TZ=Europe/Moscow`.

### 7. Настройте постоянное хранилище для базы данных (Volume)

Без этого шага файл `bot.db` живёт прямо в контейнере Railway и **обнуляется
при каждом передеплое** (любой пуш нового кода) — вы потеряете все черновики,
историю вакансий и накопленные контакты.

1. В проекте на Railway откройте вкладку **Volumes** (или Settings → Volumes)
2. **New Volume** → укажите путь монтирования `/data`
3. Добавьте переменную окружения `DB_PATH=/data/bot.db` — она уже поддерживается
   кодом (см. `db.py`, значение по умолчанию `bot.db` в текущей папке)
4. Передеплойте — теперь база будет жить в volume и переживёт любые
   последующие обновления кода

Если Volume уже пропустили и потеряли данные — увы, не восстановить, но
дальше это больше не повторится.

Если в контакте вакансии есть email — кнопка ведёт сразу на `mailto:` с уже
подставленной темой письма (название вакансии), в один клик, без открытия
бота. Счётчик кликов для таких вакансий не работает — Telegram технически
не даёт посчитать переход по прямой `mailto:` ссылке в обход бота.

Если контакт — не email, а инструкция (например «напишите в бот»), кнопка
идёт через бота как раньше, с подсчётом клика в `/stats`.

## Кнопка «Apply»

Кнопка всегда ведёт через диплинк на самого бота (`https://t.me/<бот>?start=apply_<id>`) —
это единственный тип ссылки, который Telegram разрешает в кнопках (`http(s)://`
и `tg://`; `mailto:` официально не поддерживается и вызывает ошибку
`BUTTON_URL_INVALID`). Когда кандидат нажимает кнопку, бот в личке присылает
email **текстом** (Telegram сам делает такой текст кликабельным — тап
открывает почтовый клиент), либо, если email в вакансии не найден,
показывает кнопку на `APPLY_BOT_LINK`.

Клик по кнопке считается в `/stats` в обоих случаях.

## Как пользоваться

- Пришлите боту текст вакансии в личку — бот разберёт поля и покажет превью
  с тремя кнопками: **Опубликовать сейчас** / **В очередь (дайджест)** / **Отмена**
- Можно вставлять сразу пачку вакансий, склеенных без разделителей (как
  реально присылают агентства) — ИИ сам разберёт, где заканчивается одна и
  начинается следующая
- Дайджест выходит по расписанию 09:00 / 14:00 / 19:00 — время задаётся в
  начале `main.py`, константа `DIGEST_TIMES`
- `/stats` — сводка за 7 дней: сколько опубликовано, топ-5 по кликам
- `/contacts` — список всех уникальных email/агентств, от которых приходили
  вакансии, с числом вакансий и датой последней публикации по каждому
  (список email схлопывается без учёта регистра — `Agency@X.com` и
  `agency@x.com` считаются одним контактом). Если список длинный —
  пришлёт файлом `contacts.txt`, а не сообщением
- `/autopublish on` — включить автопубликацию: вакансии без обнаруженных
  дублей будут публиковаться сразу, без ожидания вашего подтверждения.
  `/autopublish off` — вернуть подтверждение перед каждой публикацией
  (это режим по умолчанию). `/autopublish` без аргумента — посмотреть
  текущий режим. Подозрение на дубликат вакансии всегда требует ручного
  подтверждения, даже когда автопубликация включена — это защита от
  случайного повторного постинга одной и той же вакансии.
- `/testchannel` — проверяет, видит ли бот канал и какой у него статус там.
  Запустите эту команду первой, если публикация не проходит — она сразу
  покажет причину (неверный username, бот не админ и т.д.)
- **✏️ Исправить** — кнопка на черновике вакансии. Если бот разобрал что-то
  неверно, нажмите её, пришлите вакансию заново с исправленными строками
  (в том же формате: 🚢 Vessel:, 🌍 Region: и т.д.), бот запомнит пару
  "как было → как правильно" и подставляет несколько последних таких
  примеров в промпт при следующих разборах — так качество разбора
  постепенно растёт на вакансиях, похожих на те, что вы поправляли, без
  необходимости менять код каждый раз
- `/ad` — публикация рекламного поста (услуги, скидки и т.п.) без разбора
  через ИИ: пришлите любой текст следующим сообщением, бот покажет превью
  с кнопками **Опубликовать** / **Отмена** и опубликует как есть, с одной
  кнопкой **🤝 Консультация**, ведущей на `CONSULT_LINK` из `.env`

## Если публикация не работает

Отправьте боту `/testchannel`. Он либо подтвердит, что видит канал и админ
ли он там, либо покажет точный текст ошибки Telegram. Частые причины:

1. **Неверный `CHANNEL_USERNAME`** — сверьте с реальным username канала
   (Настройки канала → Изменить → Ссылка). Без `@`, но с точным регистром
   и подчёркиваниями.
2. **Бот не администратор канала**, либо у него нет права «Публикация
   сообщений».
3. **Канал приватный** без username — тогда `@username` не сработает,
   нужен числовой `chat_id` канала (напишите, если у вас такой случай —
   решение немного другое).

## Формат, в который приводится любая вакансия

```
⚓ Position

🚢 Vessel: ...        ← только если есть данные, иначе строка не выводится
🌍 Region: ...
🛂 Nationality: ...
📅 Date: ...
⏱️ Duration: ...
🔄 Rotation: ...
💰 Salary: ...

📄 Documents/Certificates:   ← весь блок пропускается, если пусто
• ...

✅ Requirements:              ← весь блок пропускается, если пусто
• ...

ℹ️ [что-то важное, что не легло ни в одно из полей выше — срочность, детали
объёма работ, тип контракта и т.п. — только если это реально есть в тексте]

📩 Contact: ...
#hashtags

🔗 https://t.me/offshoreatsea   ← ссылка на канал, всегда в конце поста
```

Поля определяются через Claude API — бот отправляет ВЕСЬ вставленный текст
(даже если это несколько вакансий подряд без разделителей — просто склеенных
одна за другой, как это часто присылают агентства) и получает обратно
структурированный список вакансий, каждая со своими полями, переведёнными на
английский. Границы между вакансиями в блоке текста ИИ определяет по смыслу
(новая должность / новый "send CV to" контакт — сигнал начала новой
вакансии), не по разделителям.

Если чего-то нет в исходной вакансии — соответствующая строка в посте просто
не появляется (без «—» и без пустых блоков). Промпт, который задаёт логику
разбора, лежит в начале `main.py` в переменной `BATCH_EXTRACT_PROMPT` — его
можно донастроить под свои нужды.
